HOODZ

A UI module for Roblox. Red and black, built from floating panels instead of one window, with its own music and its own settings.

Use itone line, then your first tab

Hoodz is a single module. The logo and the music are already part of it — nothing to host or configure yourself.

  1. [1]
    Load it. One loadstring call returns the module.
  2. [2]
    Build the window. Hoodz.new({ Title = "Hoodz" }) starts the loading sequence and hands back the UI.
  3. [3]
    Add a category, a tab, a component. Categories are the circles on the rail; tabs live inside a category.
quick-start.lua
local Hoodz = loadstring(game:HttpGet("https://raw.githubusercontent.com/animstation/HoodzGui/refs/heads/main/HoodzLib.lua"))()
local UI = Hoodz.new({ Title = "Hoodz" })

local tab = UI:CreateCategory("Player"):CreateTab("Movement")
tab:CreateToggle({ Name = "Speed boost", Callback = function(on) print(on) end })
tab:CreateSlider({ Name = "Walk speed", Min = 16, Max = 100, Default = 16, Callback = function(v) print(v) end })
Tap the logo in the top-left corner, or press RightShift, to show or hide the UI — including mid-load.

How it's builtfive panels, one shared background

Hoodz isn't one window with a sidebar bolted on. It's separate rounded panels — islands — that share one pixel-gradient background and move together. Dragging the header drags all of them.

UI methods

callreturnswhat it does
UI:CreateCategory(name)CategoryAdds a circle to the rail.
UI:CreateTab(name, categoryName?)TabShortcut — finds or creates the category, then adds the tab.
UI:SetVisible(bool)—Shows or hides the UI with a fade.
UI:Toggle()—Flips visibility.
UI:IsLoaded()booleanTrue once loading has finished.
UI:WaitUntilLoaded(timeout?)booleanYields until loading finishes. Default timeout: 30s.
UI:SetMusic(bool)—Turns the song on or off and saves the choice.
UI:SetVolume(0–100)—Sets and saves the normal volume.
UI:SetCrossfade(1–10)—Sets and saves the loop's overlap length.
UI:Destroy()—Removes the UI, the music, and every connection.

UI.Settings holds the current values: Music, Volume, Crossfade.

Toggle

Pairs up two per row. A lone toggle stays full width until its partner is created.

toggle.lua
local fly = tab:CreateToggle({
    Name = "Fly", Default = false,
    Callback = function(on) print("fly:", on) end,
})
fly:Set(true)          -- fires the callback
fly:Set(true, true)    -- silent

Fires once on creation only if Default = true. Pass NoInit = true to skip that.

Slider

Full width. Each drag has a single owner, so grabbing one never scrolls the page or drags a neighbor.

slider.lua
local speed = tab:CreateSlider({
    Name = "Walk speed", Min = 16, Max = 100, Default = 16, Increment = 1,
    Callback = function(v) print("speed:", v) end,
})
speed:Set(50); speed:Get()

Fires once on creation by default, with the default value. Same NoInit = true escape hatch.

Button

button.lua
tab:CreateButton({ Name = "Reset", Callback = function() speed:Set(16) end })

Music & settingsbuilt in, nothing to wire up

The soundtrack follows a fixed script with no setup required:

  1. [1]
    Loading. Loud, underwater — muffled highs, a slow wobble, a watery echo.
  2. [2]
    Settling. The effect and the loudness fade out over about 2.5 seconds once loading ends.
  3. [3]
    Looping. Low and clean. Near the end of the track a second copy fades in from the start while the first fades out — never a hard restart.

The last circle on the rail, Hoodz, is the built-in settings page — music on/off, a volume slider, a loop-crossfade slider, all saved and restored next run. The dock also has a quick on/off switch.

This page runs the same idea: the loop you're hearing now (if you connected) is the underwater version, continuously — the module's loading-screen sound, stretched out.

Reloadingrun it twice, get one window

Loading the module a second time — or calling Hoodz.new twice — destroys the previous UI, its music, and every connection before building the new one.

reload.lua
-- run this twice: you still end up with exactly one window
local Hoodz = loadstring(game:HttpGet("https://raw.githubusercontent.com/animstation/HoodzGui/refs/heads/main/HoodzLib.lua"))()
local UI = Hoodz.new({ Title = "Hoodz" })

Click SFX buildevery click plays gta.mp3

A second build, same API, nothing stripped out — except every interactive element plays gta.mp3 the instant you click it. The logo, the close button, a category, a tab, a toggle, a button, grabbing a slider — all of it. The sound is downloaded and preloaded into a small pool during the loading screen, so the very first click has no delay.

clicksfx.lua
local Hoodz = loadstring(game:HttpGet("https://raw.githubusercontent.com/animstation/HoodzGui/refs/heads/main/HoodzLib.ClickSFX.lua"))()
local UI = Hoodz.new({ Title = "Hoodz" })

Want a different click sound? Override it the same way the logo and music are overridden:

custom-click.lua
Hoodz.new({
    ClickFile = "myclick.mp3",
    ClickUrl = "https://raw.githubusercontent.com/you/repo/refs/heads/main/myclick.mp3",
})

This page borrows the same idea — every link, button, and copy button you've clicked so far played gta.mp3 too, if you connected audio.

Logcommon issues

The logo doesn't show
It downloads in the background the first time the module loads. If it still doesn't appear after a few seconds, a plain "H" button is used instead — the UI still works either way.
There's no music in-game
Check that Background music is on in the Hoodz settings tab and that the volume slider is above 0. The first run has to download the track, which can add a few seconds to the loading screen.
I don't hear anything on this page
Click [ connect ] on the gate screen first — browsers block audio from starting on its own. After that, check the speaker icon in the bottom-right corner isn't muted.
Clicks on this page are silent
gta.mp3 is still decoding. It's usually ready within a second or two of connecting — try again after a moment.
The UI is the wrong size in-game
Every panel scales to the screen automatically. If it still looks off on a specific device, note the device and screen size.
